# 万能转码器（中文版）

一款**完全离线**的通用格式转换工具：视频、音频、图片、文档，批量转换、容错自动补救、桌面端与网页端双形态。
转码内核为 **FFmpeg**，界面提供 **PyQt6 桌面端** 与 **Vue 3 + JSX 网页端** 两套独立形态，二者共用同一套内核逻辑。

- 软件版本：v1.0.0
- 作者：徐某
- 目录：`UniversalTranscoder-Python-CN`（中文版，本项目与英文版互相独立，可分别运行）

---

## 一、功能一览

### 1. 视频转换

支持目标格式：`mp4 / mkv / mov / avi / flv / webm / ts / mpg / wmv / 3gp / m4v / gif`

可调参数：

- 目标格式、内置预设（14 个视频预设，选中即自动回填参数）
- 质量档位（无损 / 高质量 / 标准 / 小体积 / 自定义）与恒定质量 CRF
- 分辨率（宽、高、缩放模式：等比适应 / 等比填充裁剪 / 拉伸）、帧率
- 视频编码器、视频码率、像素格式
- 旋转（0/90/180/270）与镜像（水平 / 垂直 / 双向）
- 画面裁剪、截取区间（起始时间 / 截取时长 / 结束时间）
- 变速（0.1~20 倍，画面与音频同步变速）
- 水印：图片水印 或 文字水印，可选位置（四角 / 居中）与不透明度
- 字幕烧录（srt / ass / ssa / vtt）
- 元数据（标题 / 艺术家 / 专辑 / 备注）
- 流选择（自动 / 只取第一组流 / 手动指定流序号）、丢弃音轨或视频轨
- “仅更换容器”（流复制，不重编码，秒级完成）

### 2. 音频转换

支持目标格式：`mp3 / m4a / wav / flac / ogg / opus / ac3 / aiff / amr / wma`

可调参数：音频编码器、音频码率、声道数（1/2/6/8）、采样率、音量增益（倍数或分贝）、变速、截取区间、元数据。
其中 `m4a` 提供“直接封装”预设，仅换容器不重编码，速度极快且完全无损。

### 3. 图片转换

支持目标格式：`jpg / png / webp / bmp / tiff / gif / avif / ico`

可调参数：质量、分辨率与缩放、旋转与镜像、裁剪、水印（图片 / 文字）。
另含**视频抽帧**能力：从视频中按时间均匀抽取多张快照（自动避开片头黑场与片尾字幕，有效区间取 5%~95%）。

### 4. 文档转换

- **图片 → PDF**：多张图片合并为一个 PDF，支持排序调整页序，自动处理透明通道（合成到白底）。
- **PDF → 图片**：逐页导出为 PNG / JPG，可选择 DPI 与页码范围（如 `1-3,5`）。
- **文本 → PDF**：内置极简 PDF 生成器，无需任何外部办公软件即可排版输出。

### 5. 任务队列

- 批量入队、自动去重（同源文件 + 同目标格式）
- 实时进度、瞬时速度、剩余时间、体积变化
- 开始 / 暂停 / 继续 / 停止 / 清空 / 移除选中
- 失败任务双击查看详情：错误代码、错误标题、处理建议、原始 FFmpeg 错误
- 全部完成后可自动打开输出目录

### 6. 容错与自动补救

- **错误分类**：把 FFmpeg 的原始报错归纳为 15 类（源文件损坏 / 权限不足 / 磁盘已满 / 奇数分辨率 / 缺少解码器 / 硬件加速失败
  …），并给出中文处理建议。
- **自动重试**：对两类可恢复错误自动补救后重试一次
    - 奇数分辨率 → 自动补边到偶数尺寸
    - 硬件编码失败 → **整套切换为软件编码器**重建命令（仅加 `-hwaccel none` 是无效的，因为那不会更换编码器）
- **流复制与滤镜冲突自动降级**：用户同时勾选“仅换容器”与滤镜/水印时，自动改为重新编码，避免必然失败。
- **死循环防护**：同时执行的任务数上限（默认 1，机械硬盘上最稳）。

## 三、快速开始（readme要在UniversalTranscoder-Python-CN目录下）

### 环境要求

- Windows 10 / 11
- Python 3.10 以上（开发验证环境为 Python 3.14）
- 无需单独安装 FFmpeg（内核已随项目存放在 `resources/ffmpeg/`）

### 1. 创建虚拟环境并安装依赖

```bat
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

### 2. 启动桌面端

```bat
.venv\Scripts\python.exe run_gui.py
```

### 3. 启动网页端

```bat
.venv\Scripts\python.exe run_web.py
```

默认监听 `http://127.0.0.1:8765/`，启动后会自动打开浏览器。可在“设置 → Web 端”中修改监听地址与端口。

> 也可直接运行 `python -m app.main --web --port 9000` 指定端口。
> 同一个可执行文件（打包后）同样支持 `万能转码器.exe --web` 以网页模式启动。

### 4. 构建网页端（可选，若需完整网页界面）

```bat
cd frontend
npm install
npm run build
```

构建产物输出到 `frontend/dist`，后端会自动托管。
若未构建，网页端仍可运行，但界面会退化为一个内置提示页（所有 API 依然可用）。

## 四、打包为独立可执行文件

一键构建（推荐）：

```bat
build\build.bat
```

该脚本会依次完成：建虚拟环境 → 装依赖 → 生成图标 → 构建前端 → 运行内核自检 → PyInstaller 打包。

或手动执行：

```bat
.venv\Scripts\python.exe -m PyInstaller build\UniversalTranscoder.spec --noconfirm --clean
```

产物位于 `dist\万能转码器\`，**整个目录**即为绿色版：

- 无外部依赖，可直接拷贝到任意**离线** Windows 机器运行
- 内置 FFmpeg 与 Web 端静态资源
- 已启用应用图标
- 采用 one-folder 模式（启动快、不易被安全软件误报）

## 五、自检与验证脚本

项目提供四个可复现的自检脚本（位于 `tools/`），用于验证功能正确性：

| 脚本               | 作用                                     | 运行方式                          |
|------------------|----------------------------------------|-------------------------------|
| `smoke_core.py`  | 内核链路：定位 → 探测 → 构建命令 → 执行 → 产物校验 → 容错用例 | `python tools\smoke_core.py`  |
| `test_matrix.py` | **转换矩阵**：穷举全部 30 个目标格式并逐一校验产物合法性       | `python tools\test_matrix.py` |
| `smoke_gui.py`   | 桌面端：真实构建窗口、入队、跨线程信号、表格刷新（离线无显示器亦可运行）   | `python tools\smoke_gui.py`   |
| `smoke_web.py`   | 网页端 API：系统信息 → 预设 → 转码 → 抽帧 → 文档转换     | 见文件头部说明                       |
| `make_icon.py`   | 生成应用图标（多尺寸 ico + png）                  | `python tools\make_icon.py`   |

其中 `test_matrix.py` 是验证覆盖度最高的脚本：它会真实转换全部格式，并用 ffprobe 二次校验产物
（例如确认“转出来的 .jpg 确实是一张图片，而不是伪装成 jpg 的视频流”）。

## 六、配置与日志位置

程序不会往安装目录写任何可写文件，配置与日志统一放在用户数据目录：

```
%APPDATA%\UniversalTranscoder-Python-CN\
├── settings.json     配置（JSON 明文，可手工编辑）

```

若所在环境没有 `%APPDATA%`，会自动退化为用户主目录下的 `.universal_transcoder_cn`。

## 七、实现原理简述

1. **分层架构**：`core` 完全不依赖任何界面框架，因此桌面端与网页端共享同一套转码逻辑，
   功能与行为天然一致，也便于单独测试内核。
2. **参数列表而非命令字符串**：所有 FFmpeg 调用都以参数列表（`list`）形式产出，
   彻底规避 Windows 与 Unix 的引号、空格差异，也杜绝了命令注入风险。
3. **进度解析机制**：使用 `-progress pipe:1` 让 FFmpeg 输出机器可读的 `key=value` 进度块，
   比解析人类可读的 stderr 稳定得多，且不受界面语言影响。进度块以 `progress=continue/end` 为终止标志。
4. **滤镜链顺序固定**：裁剪 → 缩放 → 旋转/镜像 → 帧率 → 水印 → 字幕 → 变速。
   顺序不可随意调换，否则会出现“旋转后坐标错乱”“水印随缩放变形”等隐蔽问题。
5. **水印与字幕走 filter_complex**：因为它们是“多输入”滤镜；此时视频流由滤镜输出标签负责映射，
   必须跳过常规的 `-map 0:v:0`，否则会产生冲突。
6. **跨线程安全**：内核回调发生在工作线程，桌面端通过 Qt 信号（队列连接）把事件切回主线程，
   网页端通过 `call_soon_threadsafe` 投递到事件循环再广播，二者都避免了跨线程直接操作 UI。
